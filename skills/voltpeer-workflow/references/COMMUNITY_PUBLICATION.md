# 社区文章编辑、复核与上线

用于把已有研究手记逐篇编辑后发布到网站。作者指定桌面版 Gemini Hydrogen「高」时，由编辑阶段确认桌面对话的实际设置并记录返修。已安装 `voltpeer-polish` 时，可用其桌面 Gemini 指南核对原稿、回稿和最终文案。

## 确认原稿和发布范围

- 读当前线上版本、源稿与发布清单，确认文章 ID 和字段对应。沿用已获批的首页设计和图库素材，将发布差量限定在作者要求的入口、署名与文章改动。
- 为每篇保留原始版本、实际编辑器回稿与最终批准稿的对应关系。批量导入先验身份、字段、数值、引文和图件，再逐篇核对实验条件、限定、证据等级与阅读顺序。批准绑定到实际送发布的文本版本。作者署名、来源、原有公开状态和示意数据标注从原稿带回。
- 用通过逐篇复核的文本替换本次目标篇目，目录里的其余篇目沿用冻结的线上内容。需要整批交付时，等全部目标篇目通过再发布。复用现有生成器，比较源稿、目录数据和静态读页的 ID、标题、作者及正文，查看移动端入口、搜索、文章页和无脚本阅读页。原始对话、未公开输入与内部回执留在工作记录，公开仓库只放经授权的源稿和分发文件。

## 发布和读回

1. 按用户授权的目标进入现有发布流程。对于 VoltPeer 的静态差量发布，核对线上父清单、发布指针与可用空间后，对最终包跑 `CHECK`。执行 `APPLY` 前刷新这些信息，只给同一通过预检的包执行一次。父清单发生变化时，重新封包和预检。空间不足时先尝试缩小可验证的差量。已有清理授权时，只处理确认可恢复的历史副本，保留当前发布与回退版本，清理后复测。发布状态不明时，先读实际线上版本和发布回执，再决定下一步。
2. 上线后通过正常 HTTPS 读回实际文件，核对发布清单和文章数据。用桌面和窄屏打开站点，实测从首页找到文章、目录搜索、详情跳转及作者位置。若移动菜单依赖延迟加载的脚本，等页面可交互后操作。站点提供静态阅读页时，禁用 JavaScript 检查可读正文和署名。
3. 同步 GitHub 时提交已核准的源稿、必要的生成器改动和实际分发文件。读回远端分支与目标提交，核对公开文件和线上发布的一致性。提交、部署回执、线上字节与浏览器验收各自记录。交付正文入口、GitHub 提交及尚待解决的实际问题。

## 已执行的社区案例

2026-11-27，VoltPeer 用桌面版 Gemini Hydrogen「高」编辑 80 篇社区手记。80 篇均通过原稿对照，33 篇恢复了有证据的原稿表述，正文总字符减少 10.9%。最终核对了两个文章目录、无脚本阅读页以及 320、390、1440 px 的真实线上阅读。篇数与尺寸来自该次发布，后续按实际内容和读者设备选取。 [站点归档提交](https://github.com/arrizabalagags-png/VoltPeerWeb/commit/567b8cf86e3bcb63fe1dc8ab89b41e75d3b16bef)
